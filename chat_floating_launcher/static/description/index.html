Odoo 13 module

Floating Chat Launcher

Moves the standard Discuss messaging menu to a fixed bottom-right launcher and adds structured request cards to direct user-to-user conversations.

What this module does

This addon extends Odoo 13's existing mail module. It does not replace Odoo Discuss or modify Odoo core files. The original messaging widget, conversations, unread counters, filters, previews, and new-message behavior are retained; only the widget location and presentation are changed.

1. Floating Discuss launcher

The normal Discuss messaging menu is moved from the top systray into a fixed circular button in the bottom-right corner. Clicking it opens the same Odoo messaging dropdown.

Unread counter Conversation previews Filters New message

2. Chat request workflow

A handshake button appears in eligible direct-chat composers. A user can send a titled request with a description, and authorized users can accept, reject, or cancel it with server-side permission checks.

Floating launcher: complete working

1
Odoo loads the backend assets

views/assets.xml extends web.assets_backend and loads the active versioned frontend files: chat_request_v3.js, floating_chat_launcher_v3.js, and both SCSS files.

2
The standard MessagingMenu is located

floating_chat_launcher_v3.js extends web.SystrayMenu, finds Odoo's existing mail.systray.MessagingMenu, and appends its element to document.body.

3
CSS changes the presentation

The class o_chat_floating_launcher makes the widget fixed at the bottom-right, gives the launcher a circular green style, retains the notification counter, and positions the dropdown above the button.

4
The existing Discuss behavior remains active

Because the original Odoo widget is relocated rather than rebuilt, its standard unread count, conversation previews, filters, new-message action, and chat opening behavior continue to work.

5
Mobile layout is adjusted

Below 576px viewport width, the button moves closer to the edges, becomes slightly smaller, and the dropdown expands between the left and right margins above the launcher.

Chat request: user workflow

1
Enable the feature for the requester

Each user has an Enable Chat Requests field on the Users form. It defaults to enabled. The composer button is shown only when this setting is enabled and the current thread is an Odoo direct user-to-user chat.

2
Open a direct Discuss conversation

Open a private one-to-one conversation containing exactly two participants. Group channels, public channels, and chats without an active user recipient are intentionally rejected.

3
Click New Request

The handshake button opens the New Request dialog. The requester enters a required title and description, then clicks Send Request.

4
Server creates the request and message

The browser calls chat.request.create_request through Odoo RPC. The server validates the user, channel, participants, title, and description; creates a chat.request record; and posts a formatted request card as a message in the same Discuss conversation.

5
The recipient sees the pending card

The card displays the request title, description, requester, and Pending approval status. The recipient sees Accept and Reject only when the required security group and recipient identity checks pass.

6
Decision requires a reason

Accept and Reject open a decision dialog. A non-empty reason is required. The server records the decision, user, timestamp, and reason, then updates the original message body.

7
The requester can cancel while pending

The requester sees Cancel only when they belong to the cancel group. Cancellation is allowed only while the request is pending and updates the same message to Cancelled.

8
Both users receive the updated card

After Accept, Reject, or Cancel, the server sends a chat_request_update notification through Odoo's channel bus. The frontend replaces the old card without requiring a page refresh.

Request states

Pending
Approved
Rejected
Cancelled

Only pending requests expose actions. Accept and Reject are recipient actions; Cancel is a requester action. Once a request reaches a final state, repeated calls return its current result instead of changing it again.

Security and permissions

The module applies permissions in both the browser and the server. Hiding a button in the browser is only a usability measure; every important action is checked again by Odoo model methods.

ControlPurposeEnforced by
Enable Chat RequestsControls whether a user can create request cards.res.users.chat_request_enabled and create_request()
Chat Request: Accept/RejectAllows a user to decide requests addressed to them.Security group plus recipient identity check in action_decide()
Chat Request: CancelAllows a requester to cancel their own pending requests.Security group plus requester identity check in action_cancel()
Internal model accessAllows regular internal users to read, create, and update request records, but not delete them through the access CSV.security/ir.model.access.csv
Important: Accept/Reject and Cancel groups are separate. Assign only the permissions needed by each role. The server also verifies channel membership, direct-chat structure, active recipient linkage, and request ownership.

Data model

The addon adds the chat.request model. Every request is tied to both an Odoo Discuss channel and the message that displays the request card.

FieldMeaning
nameRequest title.
descriptionRequest details.
channel_idDirect mail.channel conversation where the card is posted.
message_idOriginal mail.message containing the rendered request card.
requester_id / recipient_idThe sender and the other active user in the direct conversation.
statepending, approved, rejected, or cancelled.
decided_by / decided_atThe user and timestamp associated with Accept, Reject, or Cancel.
decision_reasonRequired explanation for Accept or Reject; displayed on the updated card.

The SQL constraint request_message_unique prevents more than one request record from being linked to the same Discuss message.

Installation and first-time setup

  1. Copy or keep the addon in the configured Odoo 13 custom addons directory.
  2. Restart the Odoo server so Python models and backend assets are available.
  3. Enable developer mode, open Apps, and click Update Apps List.
  4. Install Floating Chat Launcher. The addon depends on Odoo's mail module.
  5. Assign Chat Request: Accept/Reject to users who should decide requests.
  6. Assign Chat Request: Cancel to users who should cancel requests they created.
  7. Open each user record and confirm Enable Chat Requests is checked where request creation is required.
  8. Hard-refresh the browser with Ctrl+Shift+R after installation or frontend changes to rebuild/load the asset bundle.

Operational notes and limitations

  • Request creation is deliberately limited to private one-to-one Discuss chats with exactly two channel partners.
  • The other participant must be linked to an active Odoo user.
  • A request title and description are required. Accept and Reject also require a reason.
  • Request cards are stored as normal Discuss messages, so deleting the linked channel cascades to the request record.
  • Decision updates use the Odoo channel bus, so both participants can see the updated card without refreshing when the normal Discuss bus is running.
  • The addon relocates the standard Discuss widget; it does not create an independent messaging system or replace Odoo mail models.
  • If the launcher or request button does not appear after an upgrade, restart Odoo, update the module, clear/rebuild assets, and hard-refresh the browser.
